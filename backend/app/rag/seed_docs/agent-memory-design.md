# Agent 记忆系统设计：从上下文窗口到长期记忆

## 记忆的三层结构

大模型本身无状态，「记忆」全部靠外部工程实现。按生命周期分三层：

- **工作记忆**：当前请求的上下文窗口内容（system prompt、历史消息、工具结果）。容量受窗口上限约束，是最贵也最快的记忆。
- **任务记忆**：一次任务运行内的状态（计划、已完成步骤、中间发现），通常以显式状态结构持久化，跨请求恢复靠检查点。
- **长期记忆**：跨任务、跨会话沉淀的用户偏好、项目事实、历史决策，存储在数据库或向量库里，按需检索注入。

三层混用是常见错误：把该进长期记忆的事实堆在对话历史里，几轮之后窗口被灌满，早期关键信息被截断丢失。

## 上下文窗口的管理

- **历史压缩**：对话超过阈值（如 20 轮或窗口 60%）后，把早期对话摘要成一段「已发生事项」再继续。摘要由模型生成，要点是保留决策与原因、丢弃寒暄与过程。
- **工具结果不回灌**：大体积工具输出（网页、日志）只保留结论进历史，原文放外部存储、以引用形式随取。否则两三次工具调用就能吃掉半个窗口。
- **结构化注入**：system prompt 里放稳定的角色与规则，动态事实（用户偏好、当前项目背景）以独立区块注入并标注来源，便于按区块更新与淘汰。

## 长期记忆的写入与读取

1. **写入要有门控**：不是所有对话都值得记。值得沉淀的是稳定事实（用户的技术栈、代码规范）、显式纠正（「以后都用 TypeScript」）和重复出现的模式。一次性上下文（「今天临时换个说法」）写进去只会污染检索。
2. **写入即消解**：新记忆要和旧记忆做冲突检测——用户改了偏好，旧条目要么更新要么标记失效，否则检索可能同时召回新旧两条，模型无所适从。
3. **读取靠检索不靠全量**：长期记忆按向量检索（语义相关）+ 标签过滤（作用域：全局/项目/会话）双路召回，按相关度注入 top-k。全量塞进 prompt 的方式几轮就会超限。
4. **作用域隔离**：项目 A 的约定不该出现在项目 B 的会话里。记忆条目必须带作用域字段，注入时按当前上下文过滤，这是多项目 Agent 的基本卫生要求。

## 评测与失效模式

- **可复现评测**：构造「第 1 轮告知偏好 → 第 N 轮验证是否遵循」的多轮测试集，记忆系统的修改必须跑回归，否则改动很容易悄悄破坏已存记忆。
- **典型失效**：过时记忆（用户早改了方案还在旧偏好上推理）、记忆污染（把测试对话当真实约定写入）、检索噪声（注入大量弱相关记忆稀释关键信息）。三类失效对应的三道防线分别是冲突消解、写入门控、作用域过滤。
