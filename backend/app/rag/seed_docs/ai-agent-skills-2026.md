# AI Agent 开发岗位核心技能图谱（2026）

## 岗位概览

AI Agent 开发工程师负责设计、实现和运维能够自主规划、调用工具并完成多步任务的智能体系统。该岗位介于大模型应用工程与后端平台工程之间，2025-2026 年需求增长主要来自三类公司：基础模型厂商（做 Agent 平台）、 SaaS 公司（把 Agent 嵌入产品）、传统企业数字化部门（内部流程自动化）。

## 核心技术要求

### 1. 大模型应用基础
- 熟悉主流大模型 API（OpenAI 兼容协议、Anthropic、国产模型如 GLM/DeepSeek/通义）的调用方式、限流与成本结构
- 理解 prompt engineering 的结构化方法：system/user 分离、输出契约（JSON Schema）、few-shot 设计
- 掌握 Structured Output（JSON mode / function calling）的容错处理：schema 校验、修复重试、降级策略

### 2. Agent 架构与编排
- 理解 ReAct / Plan-and-Execute / Multi-Agent 等主流范式的适用场景
- 熟悉至少一种编排框架：LangGraph（图状态机）、CrewAI（角色协作）、AutoGen（多智能体对话）或自研循环
- 掌握工具调用（Tool Calling）的工程化：工具 schema 设计、超时与重试、结果截断、不可信内容隔离
- 理解人机协同节点（human-in-the-loop）的中断与恢复机制，如 checkpointer、审批流

### 3. 检索增强（RAG）
- 掌握文档解析、切块策略（chunk size / overlap）、向量检索与混合检索（关键词 + 语义）
- 熟悉至少一种向量数据库或检索引擎（见《向量数据库主流选型对比》）
- 理解评估检索质量的方法：命中率、召回率、答案忠实度

### 4. 工程化能力
- 后端：Python（FastAPI）或 Node.js，异步编程，SSE/WebSocket 流式输出
- 可观测性：token 计量、调用链追踪、成本归因、失败分类（parse/timeout/auth）
- 安全：prompt 注入防护、工具白名单、外部内容标记为不可信数据、密钥管理
- 测试：Mock LLM 的离线测试、结构化输出回归测试、端到端冒烟

## 不同公司要求的共同点

1. **「框架经验」让位于「工程判断力」**：多数 JD 不再要求精通某个框架，而要求能解释「为什么这个场景用图编排而不用线性循环」。
2. **成本与稳定性意识是分水岭**：能说出「一次 Agent 运行的 token 成本怎么算」「模型输出不合 schema 怎么办」的候选人明显稀缺。
3. **全栈倾向**：岗位要求普遍包含「能把 Agent 包装成可用的产品接口」，纯算法背景的匹配度下降。
4. **安全与评估成为标配**：2026 年的 JD 高频出现「幻觉控制」「输出评估」「注入防护」等关键词。

## 典型面试问题

- 设计一个能联网搜索并产出带引用报告的研究 Agent，画出状态图。
- 模型在连续工具调用中陷入死循环，你的系统怎么兜底？
- 如何评估一次 RAG 回答的质量？离线怎么测？
